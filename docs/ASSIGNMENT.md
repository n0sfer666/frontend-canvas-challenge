# Рабочее пространство с нодами

Сделайте небольшой редактор на React, TypeScript и React Flow (`@xyflow/react`). Пользователь собирает цепочку из нод, сохраняет её и запускает тестовую генерацию изображения. Бэкенд готов и находится в этом репозитории.

Макета нет. Достаточно понятного интерфейса для компьютера при ширине 1280 пикселей, с подписанными полями и кнопками, доступными с клавиатуры. Нужны три типа нод: **текст → генератор → результат**. Полноценный редактор сценариев делать не нужно.

## Что сделать

1. Создать рабочее пространство (space) и открыть его канвас. После перезагрузки открыть то же пространство.
2. Добавлять, перемещать и удалять ноды. В текстовой ноде — поле для описания изображения. Ноды соединяются перетаскиванием связи между портами.
3. Разрешить связи только «текст → генератор» и «генератор → результат». У каждого входа одна связь, у генератора один результат. При удалении ноды удалить её связи.
4. Сохранять ноды, связи и положение канваса через API с debounce 500 мс после последнего изменения. Во время ввода или перемещения интерфейс должен обновляться сразу. Показывать состояния сохранения и ошибку запроса.
5. По кнопке генератора сначала сохранить последние правки, затем запустить генерацию. Показать ожидание, получить итоговый статус от сервера и отобразить изображение в связанной ноде результата.
6. Предусмотреть тестовый отказ генерации и повтор. После перезагрузки восстановить граф и результаты, а незавершённую генерацию продолжить отслеживать.

Бэкенд возвращает готовую локальную картинку. Подключать внешнюю нейросеть, платить за API или загружать свои изображения не требуется.

## Что учесть в интеграции

- Серия быстрых изменений должна приводить к одному сохранению после паузы. Старый ответ не должен затирать более свежие правки; параллельные сохранения одного графа нужно упорядочить.
- Кнопка генерации должна учитывать ещё не сработавший debounce и уже отправленный запрос сохранения.
- `GET` графа возвращает `ETag`; передайте его в `If-Match` при следующем `PUT`. При `412` сохраните локальные правки, сообщите о конфликте и дайте перечитать серверный граф. Сложное слияние двух версий не требуется.
- Повтор запроса запуска после сетевой ошибки должен использовать прежний `Idempotency-Key`. Для новой генерации нужен новый ключ.
- Отказ генерации — состояние `failed` в успешном HTTP-ответе. Ответ `202` означает ожидание, а не готовое изображение.
- Остановите опрос при завершении, закрытии пространства или размонтировании страницы. Изменение графа во время генерации не должно подставлять старый результат в другую ноду.

Схемы запросов, примеры и порядок действий находятся в [инструкции API](INTEGRATION.md) и Swagger. Постоянные данные графа нужно отделить от служебных полей React Flow: `selected`, `dragging`, `measured` и функций обработки событий.

## Что посмотрим в решении

[Критерии и баллы](EVALUATION.md) опубликованы заранее: основной сценарий — 40, устойчивость — 30, интерфейс — 15, код — 10, запуск и описание — 5.

Работу нод и связей, сохранение без потери правок, понятные состояния интерфейса и читаемость кода. Также посмотрим, легко ли добавить запрос или изменить общие правила обработки ответов и ошибок без правок в компонентах нод. В README коротко объясните, как устроены debounce, очередь сохранений и работа с API.

## Как сдать

Добавьте фронтенд в `apps/web` и пришлите свой репозиторий. В README укажите команды запуска и сборки фронтенда, проверенные сценарии, недоработки и затраченное время. Бэкенд менять не нужно.

Ориентир — 6–8 часов. Сначала доведите основной путь до результата, затем проверьте ошибки и восстановление. Если не успеваете, сдайте работающую часть и напишите, что осталось. Авторизация, совместное редактирование, история отмены действий, мобильная версия канваса и деплой не требуются.

Можно пользоваться любыми библиотеками, документацией, поиском, нейросетями и помощниками для написания кода. На собеседовании нужно будет объяснить решение и внести небольшое изменение.

Это одно из двух тестовых на выбор. Выполнять оба не нужно. Решения смотрим раз в три дня; кандидатов с наиболее удачными работами приглашаем на прямое техническое собеседование.
