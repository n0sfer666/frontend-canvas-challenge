# Канвас: фронтенд решения

React 19 + TypeScript + Vite + React Flow. Пространство, ноды «текст → генератор → результат»,
сохранение графа через `PUT` с `If-Match` и имитация генерации изображения.

[Задание](../../docs/ASSIGNMENT.md) · [API](../../docs/INTEGRATION.md) · [Критерии](../../docs/EVALUATION.md)

## Запуск

Нужны Node.js 24.x и npm 11.x. Файл фиксации зависимостей — корневой `package-lock.json`.

```sh
npm ci          # из корня репозитория
npm run dev     # API на http://127.0.0.1:4001
npm run dev:web # фронтенд на http://localhost:5173 (в отдельном терминале)
```

Dev-сервер проксирует `/api`, `/assets` и `/openapi.json` на `http://127.0.0.1:4001`, поэтому
фронтенд ходит по относительным путям. Другой адрес API задаётся переменной `VITE_API_URL`
(она же используется как база запросов в собранной сборке).

```sh
npm run build:web  # сборка в apps/web/dist
npm run lint:web   # ESLint (typescript-eslint strictTypeChecked)
npm run test:web   # Vitest
npm run check:web  # линтер + тесты + сборка
```

Пространство создаётся автоматически при первом открытии, его идентификатор хранится в
`localStorage` под ключом `canvas.space`; после перезагрузки открывается то же пространство, а если
сервер его больше не знает — создаётся новое.

## Как устроен код

```text
src/api/      транспорт и контракт: http.ts, endpoints.ts, errors.ts, types.ts
src/graph/    правила и процессы: rules.ts, serialize.ts, sync.ts, generation.ts
src/app/      состояние экрана: useGraphDraft.ts, useSession.ts, App.tsx, провайдеры
src/ui/       представление: CanvasScreen.tsx, Toolbar.tsx, StatusBar.tsx, nodes/
```

Данные API (`src/api`), состояние экрана (`src/app`) и представление (`src/ui`) разделены: ноды и
панели читают готовую сессию из контекста и вызывают её действия, они не знают ни про заголовки, ни
про ETag, ни про опрос генерации.

### Один запрос — одна строка (D2)

- `src/api/http.ts` — единственное место, где собирается запрос: базовый адрес, заголовки,
  сериализация тела, разбор ответа, чтение `ETag`, обработка `204`, превращение сетевого сбоя и
  любого не-2xx в `ApiError` с кодом сервера. Ретраев и таймеров тут нет.
- `src/api/endpoints.ts` — карта путей `paths` и методы поверх транспорта. Новый запрос это строка
  в `paths` плюс вызов `http(...)`: настройка соединения не копируется.
- `src/api/errors.ts` — единственная таблица `byCode`: код ошибки → текст для человека и подсказка
  о следующем действии. Экран и ноды показывают её результат, а не свои формулировки.

Заменить транспорт (например, добавить общий заголовок авторизации) можно в `http.ts`, не трогая
ни один компонент; поменять текст ошибки — в `errors.ts`, не обходя ноды.

### Одно правило — одно место (D1)

- `src/graph/rules.ts` — таблица `nodeKinds`: заголовок, подсказка, допустимые входы, единственность
  выхода и колонка размещения. Из неё берутся и подписи в интерфейсе, и порты нод, и проверка связи
  `canConnect`, и текст отказа.
- `src/graph/serialize.ts` — перевод модели React Flow в тело `PUT` и обратно: убирает служебные
  поля (`selected`, `measured`, размеры), округляет позиции и удаляет связи с исчезнувшими концами.
  Поэтому удаление ноды не требует отдельной чистки связей.
- `src/graph/sync.ts` — очередь сохранения: дебаунс, один активный `PUT`, повтор после ошибки,
  отдельный статус конфликта, `flush()` для «сохранить прямо сейчас».
- `src/graph/generation.ts` — жизненный цикл генерации: сохранить граф, отправить запуск с
  `Idempotency-Key`, опрашивать до финального статуса, разложить результат по нодам.

`sync` и `generation` — обычные функции без React: их поведение проверяется тестами напрямую.

## Что проверено

`npm run test:web` — 61 тест, из них ключевые сценарии:

- `src/api/http.test.ts` — заголовки, `ETag`, `204`, разбор ошибок сервера и сетевого сбоя.
- `src/api/endpoints.test.ts` — тела и заголовки запросов, включая `If-Match` и `Idempotency-Key`.
- `src/graph/rules.test.ts` — совместимость типов, единственный вход, единственный выход генератора.
- `src/graph/serialize.test.ts` — очистка служебных полей и удаление повисших связей.
- `src/graph/sync.test.ts` — дебаунс 500 мс, одиночная правка, отсутствие параллельных `PUT`,
  свежая правка не затирается ответом предыдущей, конфликт 412 с сохранением черновика.
- `src/graph/generation.test.ts` — сохранение перед запуском, отказ сохранения не запускает
  генерацию, опрос до финального статуса и его остановка, повтор после потери ответа с прежним
  ключом, отклонение устаревшего результата, восстановление незавершённых генераций.
- `src/app/useSession.test.ts` — правки, конфликт и перечитывание серверного графа, лимиты графа.
- `src/ui/CanvasScreen.test.tsx` — экран целиком поверх мок-сервера MSW: успешная генерация
  показывает изображение, тестовый отказ объясняется и допускает новый запуск, правка текста
  уходит на сервер одним сохранением.

Вручную на ширине 1280: добавление трёх нод, перетаскивание, соединение портов, отказ от
несовместимой связи, удаление ноды со связями, перезагрузка страницы с восстановлением графа и
результатов, генерация обоих сценариев, обход интерфейса с клавиатуры (Tab, Enter, стрелки для
перемещения выбранной ноды).

## Известные недоработки

- Связи создаются только мышью: перетаскивание порта с клавиатуры React Flow не поддерживает,
  своей замены нет.
- Конфликт `412` предлагает перечитать серверный граф целиком; слияния черновика с серверной
  версией нет.
- Опрос генерации идёт с постоянным интервалом из `/api/config`, без нарастающей паузы.
- Позиция нод сохраняется после отпускания мыши, промежуточные кадры перетаскивания не пишутся.
